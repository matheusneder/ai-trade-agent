# Grafana dashboard smoke tests

End-to-end tests of the Grafana dashboards generated by
[`scripts/grafana_dashboards.py`](../../scripts/grafana_dashboards.py): a real Grafana, with the
project's provisioning, reads a synthetic but coherent day of the agent from an ephemeral
PostgreSQL and Loki, and Chromium (Playwright) opens every dashboard.

> **Rules for whoever changes the dashboards**
>
> - Every change to an existing dashboard requires running these tests
>   (`uv run pytest tests/grafana-dashboard-smoke-tests`) and adjusting them to the change.
> - Every new chart, metric, indicator or feature comes with more test coverage here, and,
>   when it reads data the seed does not produce yet, with that data in
>   [`tests/support/grafana_seed.py`](../support/grafana_seed.py).
> - The tests evolve together with the dashboards: a dashboard change is not done while this
>   suite is red or does not cover it.

## What is checked

| File | Needs | Checks |
| --- | --- | --- |
| `test_seed.py` | nothing | the synthetic day keeps the agent's invariants: valid position states, FKs, unique order/fill/intent IDs, PnL and fees recomputed from the fills by the domain's own functions, equity consistent with the trades, determinism per seed |
| `test_provisioning.py` | Docker | the 6 dashboards are provisioned (same panels as the generator), the PostgreSQL (`grafana_ro`) and Loki data sources are healthy, the 3 alert rules evaluate with data (`health=ok`) and stay normal |
| `test_dashboards.py` | Docker + Chromium | each dashboard loads; every panel's query returns rows without error; no panel shows "No data" or an error badge; charts draw series and tables rows; stat, table and chart values match the aggregates of the seed (equity, day PnL, drawdown, exposure, trades, win rate, profit factor, fees, exit reasons, news per source, analyst reading, LLM cost, critical events, log counts...) |
| `test_interactions.py` | Docker + Chromium | the time range picker refetches and filters (`Last 6 hours` counts only the trades of the window Grafana sent), the refresh button, the panel view, the `Serviço` and `Nível` variables and the regex search of the Logs dashboard |

Every browser test also fails on any console error, page error, failed request or HTTP
4xx/5xx response from Grafana (`/api/ds/query` included) during loading and interaction.

Values are compared on two levels: the rows Grafana received for each panel (the
`/api/ds/query` responses, matched to the panel by its query) against `Dataset.expected`,
which the seed computes from the rows it generated (not by SQL); and, for counts and labels,
the text the panel shows.

## Structure

```text
tests/grafana-dashboard-smoke-tests/
  compose.yaml          ephemeral PostgreSQL + Loki + Grafana (images from deploy/stack.yml)
  conftest.py           fixtures: stack, seed, logged-in page; deselection outside this folder
  test_seed.py          invariants of the synthetic data (fast, always runs)
  test_provisioning.py  Grafana API: dashboards, data sources, alert rules
  test_dashboards.py    each dashboard in the browser, values against the seed
  test_interactions.py  time range, refresh, panel view, variables, search
tests/support/
  grafana_seed.py       the synthetic day (also a CLI)
  grafana_stack.py      docker compose up/down, migrations, log push to Loki
  grafana_ui.py         Playwright helpers: panels, /api/ds/query capture, console/network watch
```

## The ephemeral environment

`tests/support/grafana_stack.py` runs `docker compose -p ta-grafana-smoke-<random>` on
`compose.yaml`:

- **Isolated from the real stack**: its own project name, network and tmpfs storage; ports
  published only on `127.0.0.1` and chosen by Docker (never 3000/5432). Every command carries
  the unique project name, so the `trade-agent` project and its containers are never touched.
- **Same versions and configuration as production**: the PostgreSQL, Loki and Grafana images
  are read from `deploy/stack.yml`; Grafana mounts `deploy/grafana/provisioning` and
  `deploy/grafana/dashboards` with the same startup command; PostgreSQL runs
  `deploy/postgres/init` (the `grafana_ro` read-only user the data source uses); Loki uses
  `deploy/loki/loki.yaml`.
- **Generated credentials**: the Grafana admin, PostgreSQL and `grafana_ro` passwords are new
  random values each run, passed only through the environment of `docker compose`.
- **Schema from the project's migrations**: `upgrade_to_head` (Alembic, `src/trade_agent/persistence/migrations`).
- The fixtures create it once per session and remove it (`down -v`) at the end, even on failure.
  `GRAFANA_SMOKE_KEEP=1` keeps it for debugging; remove it later with
  `docker compose -p ta-grafana-smoke-<id> down -v` (from the repository root).

**Loki and Jaeger.** The Logs dashboard reads only Loki, so Loki is part of the stack and
receives the synthetic day's logs (agent JSON lines with the `event` metadata and tracebacks,
plus the other services' lines, with the `service`/`level` labels Alloy would set): its panels
are checked like the others, values included. Covering them only "loads without error" would
let a broken LogQL query or label change through. Jaeger is left out: no dashboard queries it
(its data source is provisioned but never called, so it cannot fail a page).

## The synthetic data

[`tests/support/grafana_seed.py`](../support/grafana_seed.py) simulates a normal day of the agent
and writes it through the ORM models of `trade_agent.persistence`:

- a 5-minute price path for 8 assets (random walk, more volatile in the European and American
  hours);
- the 4h decision cycles of each enabled profile of `config/profiles.yaml` (stops and
  take-profits from the profile's protection config): entries with the OPOCO orders, fills and
  fees, exits by decision, by stop or by trailing take-profit, FOK entries that were not filled
  (`rejected`) and a manual close by a Telegram `/close`;
- the global scope paused for 30 minutes by an API error burst (`risk.state_changed`, the
  `states` of the telemetry and the API error chart agree);
- a telemetry snapshot every 5 minutes (equity, realized and unrealized PnL, peak, drawdown,
  exposure, weight, clock offset, states and per-profile results);
- news per hour following the market activity, triage and research LLM calls priced with
  `config/research.yaml`, a research report per round (one failed);
- the logs of the agent and of the other services for Loki.

The domain's own code keeps it coherent: `ensure_transition` for every state change,
`order_ids` for the client IDs, `summarize_fills`, `net_received_base`, `realized_pnl` and
`merge_fees` on the generated fills, `MarketView`/`NewsItem` for the analyst rows.

It is reproducible: the same `seed`, `hours` and `end` give the same rows. Some seeds would give
a day without, say, a losing trade; the generator then moves to the next sub-seed until every
panel has data, still deterministically.

Seed a database by hand (an **empty, migrated** one; never the production database):

```bash
uv run python -m tests.support.grafana_seed --database-url postgresql+asyncpg://trade_agent:<password>@127.0.0.1:<port>/trade_agent --seed 42 --hours 24
```

## Running

Once, install the browser:

```bash
uv sync
uv run playwright install chromium
```

Docker (Rancher Desktop) must be running. Then:

```bash
uv run pytest tests/grafana-dashboard-smoke-tests
```

A single file or test works the same way (`uv run pytest tests/grafana-dashboard-smoke-tests/test_interactions.py`).
Useful options: `--headed` (watch the browser), `--slowmo 300`, `--tracing retain-on-failure`
(Playwright trace in `test-results/`), `-x`. Environment: `GRAFANA_SMOKE_SEED` (default 42),
`GRAFANA_SMOKE_HOURS` (default 24), `GRAFANA_SMOKE_KEEP=1`.

**VS Code**: with the Python extension, the repository's `.vscode/settings.json` enables
pytest; open the Testing panel and click ▶ on the `grafana-dashboard-smoke-tests` folder (or on a
single test). Debugging works the same way (the debug ▶ of the test).

**The default run stays fast.** `uv run pytest` (whole `tests/`) deselects the E2E tests of
this folder (`e2e` and `grafana` markers): they run only when the run targets this folder or a
test of it, or with `-m e2e` / `-m grafana`. `test_seed.py` needs neither Docker nor a browser
and always runs.

A full run takes a few minutes: about 1 minute to start the stack, up to 2 minutes for the alert
rules' first clean evaluation, and a few seconds per dashboard.
